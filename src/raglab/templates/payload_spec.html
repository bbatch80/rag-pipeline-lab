Every answer on this site, every MCP tool call, and every evaluation run receives the same object: one versioned JSON payload. This is one, built by the current code for a real question.

What each part is

status
Decided upstream, never by the consumer: ok, insufficient_evidence, or out_of_scope. The consumer relays a refusal; it never invents one.
router
What the platform actually searched: the plan years and plan codes, the as-of date. Not what a model guessed.
chunks[]
The evidence, ranked. Each chunk is a complete citation unit: the text, its source (title, pages, section, content hash), the acl_basis that admitted it for this caller, and its provenance (document version, parse recipe, embedding model).
plan
The legs the platform ran (at most three, one pass) and who decided them: the model, the rules, or the caller.
warehouse_results[]
Rows from named Snowflake queries, run as the caller's role, with the columns the policy masked named as such.
payload_id
Joins this payload to its disclosure record: who asked, as which role, what exactly was delivered.

Consumers pin against spec_version; additive changes bump the minor number. The normative definition is the JSON Schema linked above.
